# Tubi — задачи бизнеса и студенческие команды

Рабочий каркас для 5-часового AI-хакатона. Бизнес уточняет задачу, подтверждает карточку и публикует её. Студенты сами отправляют предложения; бизнес вручную выбирает команду.

## Что уже работает

- Конструктор: описание → минимум 3 вопроса → ответы → редактируемая карточка.
- Рейтинг 0–100 с разбивкой, подсказками и пересчётом после редактирования.
- Подтверждение человеком, сохранение черновика, публикация и повторное редактирование.
- Каталог, поиск, фильтры, сортировка; низкий рейтинг не скрывает задачу.
- Пять демонстрационных команд, отправка откликов и ручной выбор бизнеса.
- Подтверждение выполненного этапа: 50 баллов выбранной команде, без повторного начисления.
- SQLite сохраняет данные после перезапуска. При первом запуске создаются 5 карточек и 5 откликов; в seed-файле также есть 5 слабых описаний.

## Быстрый запуск

Нужны Node.js 22.12+ и Python 3.11+. Репозиторий содержит `package-lock.json`; для frontend используйте `npm ci`.

### Windows PowerShell

Из папки проекта запустите `./start.ps1`. Скрипт устанавливает зависимости, собирает frontend и запускает приложение на **http://127.0.0.1:8000**. Остановить сервер: Ctrl+C.

Если политика PowerShell запрещает скрипт, используйте команды вручную (менять системную политику не требуется):

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
cd web
npm ci
npm run build
cd ..
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000
```

### macOS / Linux

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r server/requirements.txt
cd web
npm ci
npm run build
cd ..
.venv/bin/python -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000
```

## Разработка двумя терминалами

Backend: команда uvicorn выше, при разработке добавьте `--reload`.
Frontend: `cd web` → `npm run dev` → **http://127.0.0.1:5173**.
Vite перенаправляет `/api` на порт 8000. После изменения production frontend нужен новый `npm run build` и перезагрузка страницы.
API-документация: **http://127.0.0.1:8000/docs**. Проверка состояния: `/api/health`.

## OpenAI и деморежим

Скопируйте `server/.env.example` в `server/.env`, задайте `OPENAI_API_KEY` и при необходимости `OPENAI_MODEL`, затем перезапустите backend. По умолчанию указана `gpt-4o-mini`; модель должна быть доступна вашему API-проекту и поддерживать Structured Outputs. API использует отдельный ключ и биллинг.

Без ключа приложение проходит демонстрационный сценарий на локальных шаблонах: вопросы выбираются по незаполненным полям, ответы переносятся в карточку. Явные метки «Данные:», «Пользователи:» и их казахские аналоги распознаются; несколько простых правил находят, например, упоминание CSV. Копируются исходные фрагменты, без генерации фактов. Произвольный текст эти правила понимают ограниченно. `mode=fallback` и предупреждение явно обозначают резервный режим.

С ключом сервер использует Responses API и Pydantic [по официальной документации OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Внутренний ответ содержит цитату и источник для каждого заполненного текстового поля. Сервер проверяет точное наличие цитаты в описании или конкретном ответе пользователя и совпадение значения поля с цитатой. Текст вопроса источником фактов не считается. Неподтверждённое поле становится `null`, возвращаются `missing_fields` и предупреждение. Цитаты и служебные данные не выходят в публичный JSON.

Сервер сохраняет явно указанные сведения, пропущенные моделью, с помощью того же локального извлечения. При уточнении возвращаются минимум три разных вопроса с целевыми полями; вопросы о заполненных полях заменяются. Если основных пробелов меньше трёх, задаются вопросы о дополнительных деталях доступа, приёмки или границ первой версии. При сборке карточки `questions=[]`.

Такая проверка уменьшает выдумки, но не доказывает, что цитата верно отнесена к полю, не содержит противоречий и соответствует действительности. Карточка остаётся редактируемой и требует подтверждения человека. Генерация использует строгий перенос фрагментов вместо свободного пересказа. При отказе, неполном ответе, ошибке, таймауте или неправильном формате включается явный fallback. Таймаут — 20 секунд, повторы отключены, `store=False`. Логи содержат только класс ошибки, без ключей, полных описаний и ответов провайдера.

### Язык API

Необязательный заголовок `Accept-Language: ru` или `Accept-Language: kk` выбирает язык вопросов, предупреждений, ошибок и подсказок рейтинга. По умолчанию — `ru`; поддерживаются также `kk-KZ` и списки с `q`. Пользовательские описания, карточки и отклики автоматически не переводятся. Сами коды ошибок, статусы и названия JSON-полей остаются прежними. `/health` показывает наличие ключа, а `mode` конкретного ответа — фактически использованный режим.

## Архитектура и разделение команды

| Владелец | Папки | Ответственность |
| --- | --- | --- |
| Участник 1 | `web/src/features/business/`, `web/src/shared/`, `web/src/App.tsx`, настройки frontend | Конструктор, общий интерфейс и подключение экранов |
| Участник 2 | `web/src/features/marketplace/` | Каталог, карточка, отклики и решение бизнеса |
| Участник 3 — backend | `server/`, `contracts/`, README | API, SQLite, AI, рейтинг и контракт |

`contracts/api.md` — договор, `contracts/types.ts` — типы frontend, `contracts/fixtures.json` — примеры для независимой работы. Все экранные запросы находятся в `api.ts` своего модуля. Главный интерфейс использует настоящий локальный backend. Для работы на заглушках импортируйте примеры из fixtures в адаптер своего модуля. Общие зависимости и контракт изменяйте согласованно.

Backend:

- `main.py` — фабрика приложения, запуск, подключение маршрутов и раздача сайта.
- `routes/tasks.py`, `routes/proposals.py`, `routes/ai.py` — HTTP-маршруты с явными моделями ответов.
- `services.py` — правила карточек, публикации, независимых решений и подтверждения этапа.
- `db.py` — SQLite и репозиторий; `seed.py` — однократное заполнение пустой базы.
- `ai.py`, `ai_grounding.py`, `ai_questions.py` — вызов модели, проверка источников, локальное извлечение и вопросы.
- `schemas.py`, `settings.py`, `errors.py`, `localization.py`, `rating.py` — общие модели, настройки, ошибки, языки и правила рейтинга.

База по умолчанию: `server/data/tubi.sqlite3`; путь меняется через `TUBI_DB_PATH`. Каждая операция чтения/изменения использует одну транзакцию; записи начинаются с `BEGIN IMMEDIATE`. Конкурирующие решения и подтверждения этапа выполняются последовательно. Повторное подтверждение не добавляет баллы. Seed и его маркер записываются атомарно, существующие записи не заменяются; даже база без маркера с пользовательскими записями не заполняется демоданными.

## Формула рейтинга

| Категория | Вес | Проверка |
| --- | --- | --- |
| Контекст и потребность | 20 | 10 за context, 10 за need |
| Данные | 20 | data |
| Результат | 15 | expected_result |
| Критерии успеха | 15 | success_criteria |
| Ограничения | 10 | constraints |
| Пользователи | 10 | users |
| Связь с бизнесом | 10 | 5 за contact, 5 за interaction_format |

Засчитывается текст длиной от 3 символов после нормализации пробелов, содержащий буквы/цифры. Пустые значения и известные заглушки («не знаю», «не указано», «білмеймін», «белгісіз», «тест» и др.) дают 0. Регистр и завершающая пунктуация заглушки не влияют на результат. Это проверка наличия сведений: она не доказывает качество решения, правдивость фактов или реальную готовность бизнеса. Произвольный бессмысленный текст может получить баллы. Полные правила находятся в `rating.py`. AI баллы не начисляет.

0–39 — нужно уточнение; 40–69 — рабочая; 70–89 — готова; 90–100 — приоритетная. При текущих весах итог кратен 5; пограничные значения 39/69/89 дополнительно проверяются в функции определения уровня. Подтверждённый черновик скрыт из общего каталога до отдельной публикации. Опубликованная задача с любым рейтингом видна и принимает отклики. При сохранении изменённых сведений сервер заново считает рейтинг, в том числе уменьшает его при удалении данных. Лишние поля `score`, `rating`, `status`, `points` в запросах сохранения отклоняются; `confirmed` должен быть JSON boolean. Выбор команды не зависит от рейтинга и не автоматизируется.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r server/requirements-dev.txt
$env:PYTHONPATH='server'
.\.venv\Scripts\python.exe -m unittest discover -s server/tests -v
cd web
npm run build
```

На macOS/Linux: `PYTHONPATH=server .venv/bin/python -m unittest discover -s server/tests -v`.
API-проверки используют временные SQLite и подменённый клиент OpenAI, не читают настоящий ключ и не тратят API-бюджет. Проверяются границы уровней, удаление данных, заглушки RU/KK, JSON модели, отказ, таймаут, неправильный ответ, цитаты, минимум три разных вопроса, языки, подтверждение и публикация, низкий рейтинг, независимые и конкурентные решения, однократные баллы, откат транзакции и сохранность после повторного запуска приложения. Включён полный сценарий от описания до выбора команды. Настоящий OpenAI API в этой работе не вызывался.

Перегенерация примеров и OpenAPI: `python scripts/export_contracts.py` из корня с активным окружением проекта.

### Совместная проверка с frontend

1. Ввести: «Мы вручную читаем отзывы гостей кофейни в Алматы». Проверить три вопроса; без ключа виден `fallback`.
2. Ответить: потребность — «Группировать отзывы по темам»; данные — «CSV из 100 обезличенных отзывов»; результат — «Таблица тем с примерами отзывов».
3. Собрать карточку. В fallback рейтинг вырастает с 10 до 55. Добавить пользователей «Менеджеры кофейни»: 65. Удалить данные: 45; вернуть: 65. В live фактическая разбивка зависит от извлечённых сведений.
4. Подтвердить сведения и опубликовать. Проверить видимость в каталоге и отправить два отклика от разных команд.
5. В роли бизнеса принять один отклик: второй остаётся `pending`. Подтвердить этап дважды: у первого отклика остаётся 50 баллов.
6. Повторить запросы с `Accept-Language: kk`: системный текст на казахском, пользовательский текст прежний. После перезапуска сохранённые карточка и решения остаются.

Информация для обоих frontend-участников о совместимости: `contracts/api.md`, раздел «Backend quality handoff». Совместная ручная проверка с участниками выполняется отдельно от автоматических API-тестов.

## Демонстрация за 5 минут

1. Каталог: покажите разные уровни готовности и фильтры.
2. В роли «Бизнес» нажмите «Создать задачу», затем «Попробовать пример».
3. Ответьте на три вопроса, соберите карточку; покажите текущие баллы.
4. Добавьте пользователей, измеримый критерий успеха и контакт; покажите рост рейтинга.
5. Подтвердите сведения и опубликуйте задачу.
6. Переключитесь в «Команда», найдите задачу и отправьте предложение.
7. Вернитесь в «Бизнес», откройте отклики и вручную выберите команду.
8. При наличии времени покажите подтверждение выполненного этапа.

## Ограничения каркаса

Это локальная демонстрация: переключатель ролей не является авторизацией, данные бизнеса общие. Нужны настоящая аутентификация и проверки владельца перед использованием реальных данных или публичным размещением. Сервер по умолчанию слушает только 127.0.0.1. Чат, регистрация и проектный трекер не входят в MVP. Шрифт Manrope загружается из Google Fonts; без сети используется системный шрифт.
